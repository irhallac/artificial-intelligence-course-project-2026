Course project

LLM and VLM reasoning in Turkish and English

Groups of 2–3 students will choose one of the three listed project areas or propose another project. Each group will prepare test questions with known answers, evaluate language or vision-language models, and report the results.

The experiment

Choose one project area and one main question. The result must come from a fixed test set evaluated under every planned condition, not from a few selected prompts.

  1. Create base cases. Store the underlying spatial arrangement, event structure, or visual scene in a form that a small fixed-rule program can use.
  2. Prepare matched versions. Write every case in standard Turkish and equivalent English. Add only the other version needed for the group's comparison.
  3. Run a pilot. Use 5–10 cases to check the program, prompts, model access, answer scoring, and cost.
  4. Fix the experiment. After the pilot, keep the test cases, conditions, prompts, and settings unchanged. The default minimum is 50 base cases.
  5. Run and record. Evaluate all planned cases and retain the complete, unedited model responses.
  6. Measure and explain. Report accuracy for every model and condition, then examine repeated errors.

Complete the project plan before producing the full test set. A different test-set size requires approval in the plan.

Project options

Examples and full descriptions

  1. Spatial reasoning

    Combine several relations and study the effects of language, sentence order, irrelevant information, or Turkish expression.

  2. Temporal reasoning

    Recover event order from before-and-after relations, indirect descriptions, changing states, or incomplete information.

  3. Text and diagram reasoning

    Give the same spatial scene to a VLM as Turkish text, English text, a diagram, or text with a diagram.

  4. Propose your own project

    Propose another specific LLM or VLM reasoning task using checkable answers and controlled comparisons.

Choosing models

Choose a small number of models that the group can run consistently. Record the exact model names, versions, access method, prompts, and settings.

Possible Turkish or Turkish-adapted models include models from COSMOS, Trendyol, Turkcell, WiroAI, Kumru, Kanarya, and METU NLP's LlamaTurk. Multilingual model families include Qwen, Gemma, Llama, and Mistral. This is neither a required list nor a ranking.

For text projects, a Turkish model and a multilingual model form a useful comparison. Another combination is acceptable if it fits the research question. For the visual project, use the same VLM in every presentation condition; Trendyol Asure is one possible VLM.

Results

For every model and condition, report:

  • number correct and total;
  • accuracy;
  • number of missing, invalid, or unscorable answers.

Invalid answers remain in the total and receive a score of incorrect. For tasks with a fixed answer set, report the number of cases for each correct label. If the labels are not reasonably balanced, also report the accuracy obtained by always choosing the most frequent label.

Define and test the automatic scoring rule before the full run. A label must not be accepted merely because it occurs inside another label, such as kuzey inside kuzeybatı. Do not repair model responses by hand.

Because conditions use the same base cases, also identify which cases change from correct to incorrect and from incorrect to correct. Group repeated errors into a few categories and use representative examples to explain the numerical results.

Further investigation optional

After the main experiment and error analysis, the group may test a method intended to improve the result. Possible directions include changing the prompt, providing selected examples, requesting an intermediate representation, using a calculation tool, changing the data or presentation, or fine-tuning an open-weight model with LoRA or QLoRA.

This list is not exhaustive. Explain why the method was chosen and compare it with the original result on the same unchanged test set. Report decreases and failed attempts as well as improvements.

Submission

Submit one GitHub repository per group. The repository's README.md is the final report; a separate PDF is not required.

README

Write a concise paper-style report containing:

  • title, group members, and video link;
  • abstract and research question;
  • brief related work;
  • test set and method;
  • models, prompts, settings, and scoring rule;
  • results and error analysis;
  • optional improvement study, if conducted;
  • conclusion, limitations, and references;
  • a short statement describing any use of AI assistants.

Repository contents

Include the base cases, correct answers, Turkish and English versions, code, prompts, unedited responses, scored results, figures or tables, and instructions for reproducing the experiment.

Video

Prepare a 5–10 minute video. Every group member must appear on camera and explain part of the work. Show the research question, the answer program, the main results, one error, and the conclusion. Place an accessible video link near the top of the README; do not commit the video file to GitHub.

Final submission

The repository must be public, or the instructor must have access before the deadline. Submit its URL through the course submission link.
